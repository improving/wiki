# Agentic Development Is Eleven Problems, Not One — Summary

**Original source**: `references/devlinliles.com/agentic-development-is-eleven-problems-not-one/agentic-development-is-eleven-problems-not-one.md`

## Summary

Devlin Liles argues that most agent projects fail because teams treat agentic development as one problem when it is eleven distinct competency areas, each with its own vocabulary, failure modes, and tooling. He organizes them into four stacked layers — Foundation, Operational, Governance, and Intelligence — and frames them as Lego bricks that can be assembled from wherever the current problem demands. This post is the map for an eleven-post series.

## Key Claims

- The four layers are Foundation (Execution, Coordination), Operational (Memory, Context Management, Error Handling), Governance (Definition, Auditing, Intervention), and Intelligence (Planning, Evaluation, Improvement).
- Skipping a block is felt in the layers above: no Definition means Execution heads confidently the wrong way; no Memory leaves Improvement nothing to write into.
- The most common failure pattern: a solid Foundation, minimal Governance for compliance, then a stall — able to say what happened but unable to measure or improve.
- The Intelligence layer holds the compounding value promised by agentic AI, and most teams have not built there.
- Coordination and Context Management rarely appear in canonical "how to build agents" lists but matter enormously in production.
