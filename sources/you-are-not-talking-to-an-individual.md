# You Are Not Talking to an Individual — Summary

**Original source**: `references/devlinliles.com/you-are-not-talking-to-an-individual/you-are-not-talking-to-an-individual.md`

## Summary

Liles applies Charles Sanders Peirce's type-token distinction to language models: the weights are the type, and every inference run is a token — a single type manifesting as billions of simultaneous tokens. He draws out three implications for enterprise deployments. Continuity is a design fiction, since what persists is an external state file the model reads at session start, not the model itself. Consistency is technically false, because inference is stochastic and varies across regions, hardware, and quantization. And identity is absent: there is no continuous self accumulating across tokens. The design obligation is to build context management and consistency auditing explicitly.

## Key Claims

- The model weights are the type; every API call, conversation, and session is a token instantiated from it.
- The experience of continuity is a product design choice, not a property of the model — it evaporates when context is exceeded, state is lost, or the model version changes.
- Even at temperature zero, floating-point and hardware-parallelism details introduce variation; the model gives answers from a distribution, not identical answers.
- There is no persistent self: each token runs and ends, and the feeling of a bond is generated by a token that does not transfer to the next.
- Enterprise practice should treat model state as external infrastructure and audit distribution stability rather than spot-check responses.
