# Recall Is the Standard Only One Side Can Meet — Summary

**Original source**: `references/devlinliles.com/recall-is-the-standard-only-one-side-can-meet/recall-is-the-standard-only-one-side-can-meet.md`

## Summary

The post walks through a six-step regulatory sequence David Sacks described on All-In and argues that none of the steps requires banning anything, yet the sequence functionally bans open-weight models. The hinge is step five: a standard requiring a model to stay continuously monitorable and recallable after release measures a property only a centrally hosted model can have. Applied evenhandedly, the rule is passed by one architecture and failed by the other, because the standard was written around a property distributed unevenly across the industry.

## Key Claims

- The six steps: set a safety standard, require pre-release testing, write it into law, apply it evenly, watch open models fail, restrict what failed — the word "ban" never appears (All-In Ep. #286, Aug 21).
- A closed model lives behind an API the lab controls: usage is metered, a flawed version swapped in an afternoon, every call observable; released weights cannot be reached or pulled back.
- Equal application produces an unequal outcome when the standard tests for post-release monitoring and recall.
- Alternative designs — release-time testing, license terms, staged disclosure — are equally defensible but do not fail open weights on architecture alone.
- A recall-based standard shifts the compliance burden onto whoever deployed the model, flagging already-deployed open-weight models as unrecallable regardless of their eval scores.
