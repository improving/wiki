# Technical Debt Is a Chronic Condition, Not a Single Decision — Summary

**Original source**: `references/devlinliles.com/technical-debt-is-a-chronic-condition-not-a-single-decision/technical-debt-is-a-chronic-condition-not-a-single-decision.md`

## Summary

Argues that the operative word in technical debt is "continually": it is the eventual consequence of repeatedly trading craftsmanship for short-term velocity, not a single documented decision. Ward Cunningham meant a deliberate, one-time tradeoff; what teams actually experience is a default made every sprint because no sprint leaves room to do it right. The root is behavioral, and AI-assisted development escalates the accumulation rate.

## Key Claims

- A single skipped-test decision costs an afternoon; a year of them compounds into a codebase nobody understands.
- Debt is distributed across thousands of small decisions, not a discrete backlog item, so "we'll pay it back later" rarely happens.
- Technical debt is a behavioral problem with technical symptoms: slow builds, fragile tests, undocumented interfaces, high defect rates.
- You cannot fix a behavioral problem with technical solutions; refactoring without changing decision-making reproduces the debt.
- The intervention is to name the recurring pattern and set explicit non-negotiables; the definition of done is a prevention mechanism.
- AI removes the last natural governor on debt accumulation, making craftsmanship standards more important, not less.
