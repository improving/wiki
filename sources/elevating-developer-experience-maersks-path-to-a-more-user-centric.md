# Elevating Developer Experience: Maersk's Path to a More User-Centric Internal Development Platform — Summary

**Original source**: `references/improving.com/elevating-developer-experience-maersks-path-to-a-more-user-centric/elevating-developer-experience-maersks-path-to-a-more-user-centric.md`

## Summary

Internal Developer Platforms are too often treated as pure technical tools that need little design effort, when they should be built with user-centric methodologies. Using Maersk's journey, the post argues that a successful IDP needs a clear vision, significant time and executive backing, journey mapping, and relentless focus on the developer's experience.

## Key Claims

- There is a widespread misconception that IDPs are merely technical tools requiring little development effort, or that one solution fits every business.
- Maersk's IDP project lasted 18-24 months, showing the commitment required, and depended on executive support and budget.
- User-centric research should pick models by intent: individual models (personas), contextual/goals models (experience maps), and future-state models.
- Maersk's legacy infrastructure left developers waiting indefinitely for support; the IDP cut provisioning wait times and enabled self-service.
- The IDP standardized security practices and commit formatting, reducing cognitive load so developers could focus on product work.
- Key practices included user-centered design, friendly onboarding, continuous feedback loops, performance, accessibility, documentation, and user testing.
- Lessons: invest in training, manage stakeholder expectations, acknowledge the IDP cannot cover every use case, and secure executive sponsorship.
