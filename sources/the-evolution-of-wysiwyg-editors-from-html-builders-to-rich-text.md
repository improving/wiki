# The Evolution of WYSIWYG Editors — Summary

**Original source**: `references/improving.com/the-evolution-of-wysiwyg-editors-from-html-builders-to-rich-text/the-evolution-of-wysiwyg-editors-from-html-builders-to-rich-text.md`

## Summary

The original promise of WYSIWYG was to let non-technical users build complete, well-structured HTML pages visually. That has largely given way to content-focused rich text composers that operate inside predetermined structural frameworks. The post traces this shift across three eras and argues that modern tools gained accessibility and performance at the cost of structural control and HTML transparency.

## Key Claims

- WebMagic, by Silicon Graphics, was the first WYSIWYG HTML editor; Vermeer FrontPage followed in November 1995 and was acquired by Microsoft in 1996 for $133 million.
- The golden age (1995–2005) was desktop HTML builders — FrontPage, Dreamweaver, PageMill, Arachnid — with direct visual manipulation, real-time preview, and standards-compliant output.
- Microsoft's Internet Explorer 5.5 introduced `contentEditable` and `designMode`, the APIs that underpin all browser-based editors.
- 2005–2015 brought JavaScript libraries — TinyMCE (2004), CKEditor, Quill (2014) — alongside CMS proliferation and Web 2.0, shifting focus from HTML building to content within predefined structures.
- Modern editors (Gutenberg, Notion) favor block-based creation, semantic structure, responsive template output, and cross-platform compatibility.
- Constraints driving the change: browser inconsistencies, mobile-first design, XSS/injection risk, and performance.
- Structured content — headless CMS, API-first delivery, component design systems — separates content from presentation; email template builders like Topol.io and MJML are the closest modern analogue to the original WYSIWYG.
