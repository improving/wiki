# Clients Do Not Buy Tests or Beautiful Code — Summary

**Original source**: `references/improving.com/clients-do-not-buy-tests-or-beautiful-code/clients-do-not-buy-tests-or-beautiful-code.md`

## Summary

Claudio Lassala argues that clean code and tests are not what clients value — they value having a problem solved, and they retell stories about relief, not craftsmanship. Borrowing an analogy of an English-speaking crew leader, he urges developers to learn the client's language (accountants say "debit" first), listen actively, and present tests and code in terms the business recognizes.

## Key Claims

- Clients do not talk about clean code or tests; they talk about problems being solved.
- Developers who speak only technical jargon cannot understand business leaders' needs, unlike a bilingual crew leader who earned more by communicating.
- Accountants articulate work as "debit bank undeposited funds, credit accounts receivable"; code and tests should mirror that language.
- Watching stakeholders draw their vision at a whiteboard should inform UX/UI work — experience first, interface second.
- Showing clients automated tests that document their needs builds understanding and trust.
- The author's rule: "our job is to make your clients happy. If we succeed, we guarantee you'll be happy."
- Steve Jobs' reported insistence on elegant iPhone internals is used as an analogy for neatness signaling care.
