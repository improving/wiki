# Creating Better Data Visualization Experiences: Part 1 of 2 — Summary

**Original source**: `references/improving.com/creating-better-data-visualization-experiences-part-i/creating-better-data-visualization-experiences-part-i.md`

## Summary

Designing for data-driven insight differs from a typical user-centric web experience: instead of funneling users down a single path, it must support branching exploration. The first of two parts covers UX processes unique to data visualization and the discovery questions that should frame an analytics product.

## Key Claims

- Traditional user-flow rules — clear purpose, a single guided path, demonstrating task completion — break down when the goal is exploration.
- A dashboard's options multiply fast: charts × filters × sortable fields and toggles becomes a maze of divergent paths.
- Most data-driven products need a branching, not linear, user journey; complexity and unpredictability are expected.
- UX has shifted from personality-based personas toward task-based framing, and many experts favor the Jobs to Be Done framework.
- Users arrive with predefined questions; discovery via user interviews, empathy mapping, and user stories surfaces them.
- Discovery should answer who the data is for, what benefit the visualization provides, what mental models and terminology apply, and how it can be tested.
