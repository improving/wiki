# DevOps Was Always a Trust Problem — Summary

**Original source**: `references/devlinliles.com/devops-was-always-a-trust-problem/devops-was-always-a-trust-problem.md`

## Summary

The post argues that by 2018 DevOps tooling was mature yet adoption stalled because organizational leadership did not trust development teams — so deploying tooling first, expecting trust to follow, fails. Tooling in a low-trust environment gets adopted defensively and never delivers ROI, reinforcing the gap. The author extends the argument to agentic AI: autonomy deployed without trust infrastructure gets shut down for the same reasons.

## Key Claims

- The 2018 obstacle was human, not technological: leadership distrusted automated deployments, faster iteration, and reduced process overhead.
- Tooling deployed before trust is surrounded by manual checkpoints, optional builds, and un-automated production, so it can't deliver value.
- The lack of ROI is then misread as proof the tooling is worthless, deepening the trust gap.
- The effective sequence establishes trust conditions first, demonstrates reliability in low-stakes contexts, then extends autonomy.
- Agentic AI is failing for the same reason: agents are deployed without defining permissions, error handling, auditing, or human approval points.
- The governance engine — audit trails, boundary enforcement, quality gates, approval points — is the AI-era trust infrastructure.
