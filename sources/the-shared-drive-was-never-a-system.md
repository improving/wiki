# The Shared Drive Was Never a System — Summary

**Original source**: `references/devlinliles.com/the-shared-drive-was-never-a-system/the-shared-drive-was-never-a-system.md`

## Summary

Argues that the shared drive, folder tree, email, wiki, and chat search organizations rely on were never built as knowledge systems — they are places to put things, not ways to find them again. Because a tree lets a document live in only one place, it breaks as soon as the organization outgrows the assumptions baked into it. Tribal knowledge fills the vacuum with excellent precision and a single point of failure nobody puts on a risk register.

## Key Claims

- Well over three-quarters of Improving's clients run at least one critical process off a shared drive and Excel workbook on first engagement.
- Keyword search can't weigh files by currency, approval, or truth, and will rank an 18-month-old draft above the version actually in use.
- Vocabulary defeats search: "expense report" finds nothing when the document is titled "T&E Guidelines."
- In almost every organization evaluated, the real search index is a person — a single point of failure.
- The next instinct (tag things, build a taxonomy, standardize terms) is correct but incomplete; taxonomies decay for reasons unrelated to how well they were designed.

## Relevance

Foundational for enterprise retrieval work: it explains why [keyword search](/concepts/keyword-search.md) and [vocabulary mismatch](/concepts/vocabulary-mismatch.md) are structural problems, and why [tacit knowledge](/concepts/tacit-knowledge.md) substitutes for a system that was never built.
