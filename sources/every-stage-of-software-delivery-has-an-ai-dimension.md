# Every Stage of Software Delivery Has an AI Dimension — Summary

**Original source**: `references/devlinliles.com/every-stage-of-software-delivery-has-an-ai-dimension/every-stage-of-software-delivery-has-an-ai-dimension.md`

## Summary

Most organizations investing in AI for development find one clearly useful spot — usually code completion — and mistake it for a strategy. Liles argues delivery is a continuous eight-stage loop (Plan → Code → Build → Test → Release → Deploy → Operate → Monitor) and that every stage has its own AI leverage point. Because quality improvements at early stages reduce cost at later ones, the gains compound into an "AI-native delivery" system rather than eight independent tool investments.

## Key Claims

- Delivery is a loop of eight stages; code completion addresses only one of them.
- AI in Plan can catch ambiguous, contradictory, or incomplete requirements before code is written — the cheapest place to fix defects.
- AI in Build (test selection, dependency analysis) and Test (edge-case generation, flaky-test detection) is underinvested.
- Deploy benefits from AI-monitored progressive rollout with automatic rollback; Monitor from anomaly detection that cuts alert fatigue.
- Start where you have the most quality problems, wasted time, or risk — not by asking which AI tool to adopt.

## Relevance
