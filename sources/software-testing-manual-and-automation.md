# Software Testing - Manual and Automation — Summary

**Original source**: `references/improving.com/software-testing-manual-and-automation/software-testing-manual-and-automation.md`

## Summary

Bhawna Srivastava contrasts manual and automated testing, arguing automation excels at fast, repeatable regression checks while manual testing retains advantages in usability, exploratory work, edge cases, and complex systems. She recommends a combined strategy and lists eight practices for integrating automation into a testing strategy.

## Key Claims

- Manual testing relies on human observation, intuition, and experience; automation runs pre-written scripts faster and across multiple environments.
- Automation is especially valuable for regression testing: faster, more consistent, wider coverage, and earlier feedback.
- Automation limits: high setup and maintenance cost, reduced tester creativity, false positives, and poor coverage of UX and usability.
- Manual testing surfaces usability and edge cases automation misses and can validate automated results.
- Best practices: automate regression tests first, plan the strategy, pick fitting tools, train the team, integrate into CI, maintain tests, collaborate, and monitor results.
- The future brings more automation, but exploratory and usability testing will still need humans.
