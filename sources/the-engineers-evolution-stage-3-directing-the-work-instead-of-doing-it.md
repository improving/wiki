# The Engineer's Evolution, Stage 3: Directing the Work Instead of Doing It — Summary

**Original source**: `references/devlinliles.com/the-engineers-evolution-stage-3-directing-the-work-instead-of-doing-it/the-engineers-evolution-stage-3-directing-the-work-instead-of-doing-it.md`

## Summary

Stage 3 is where the engineer's day visibly changes: they document how they work, encode it into personal task agents and skills, and move from the keyboard to directing and reviewing output. Agents at this stage reflect one engineer's judgment, so throughput rises without lowering their bar. The developer becomes a director and reviewer; the tester becomes a test designer whose coverage is no longer capped by typing speed.

## Key Claims

- A skill is a written job description for a unit of work: how to do this thing plus the context required to do it well.
- A healthy Stage 3 runs at roughly 92–94% acceptance on agent output; below the band signals weak trust or definitions, above it signals over-trusting.
- Signature skills are prompt and context engineering, writing skills an agent can be evaluated against, critical review of generated code, and the coding depth to step in when an agent is weak.
- Automation coverage breaks its long-standing labor cap once well-designed tests can be generated from acceptance criteria.
- The people analogy is useful but warns that agents fail differently, producing confidently wrong output on trivial tasks where a colleague would not.
