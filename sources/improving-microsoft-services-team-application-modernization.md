# Improving Microsoft Services Team: Application Modernization — Summary

**Original source**: `references/improving.com/improving-microsoft-services-team-application-modernization/improving-microsoft-services-team-application-modernization.md`

## Summary

Part 2 of a series on Improving's Microsoft Services Team focuses on application modernization — shifting to a cloud-first approach, often via lift-and-shift. It illustrates the work with a Fortune 500 health insurer whose enterprise data strategy Improving rebuilt on Microsoft Azure, using Kafka to speed ingestion into Snowflake as the centralized data hub.

## Key Claims

- Application modernization commonly means moving to a cloud-first approach; lift-and-shift lets companies migrate existing on-premises technology without rebuilding from scratch.
- Common drivers Improving sees: wanting to leverage AI/ML, security concerns with aging applications, data access, application compatibility, and process or organizational efficiency.
- A Fortune 500 health insurer in a regulated industry struggled with data integration, inconsistent data, no central location, and no clear ingestion/consumption patterns.
- Improving designed an enterprise-wide data fabric, self-service data mart, and advanced analytics, combining Azure and Kafka to speed ingestion to Snowflake as the data warehouse.
- Improving built custom API management software and self-service tools, and trained the client's data engineering team to automate manual tasks.
- The architecture eliminated years of technical debt, removed silos, and created unified data ingestion and consumption patterns.
