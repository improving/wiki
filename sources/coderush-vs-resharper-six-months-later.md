# CodeRush vs. ReSharper: Six Months Later — Summary

**Original source**: `references/devlinliles.com/coderush-vs-resharper-six-months-later/coderush-vs-resharper-six-months-later.md`

## Summary

After six months bouncing between the two major [Visual Studio](/entities/visual-studio.md) productivity add-ins, Devlin Liles documents a head-to-head comparison across community/plugins, usability, code generation, refactoring, file generation, and support/install/licensing. He concludes he will continue to use and recommend [ReSharper](/entities/resharper.md), driven by ease of refactoring, template power, his own plugin work, and file/solution-level refactorings — while stressing that both are great products and that the real lesson is to re-evaluate the tooling often.

## Key Claims

- [CodeRush](/entities/coderush.md) has a slightly more active plugin community and wins on code generation: context-aware mnemonic templates that change output based on context such as implemented interfaces.
- ReSharper's single set of key bindings and deep navigation make refactoring feel like a normal part of the workflow.
- CodeRush's core product has a notable gap: no ability to generate a new file (class, interface, enum, struct, folder) from the solution explorer; ReSharper has it and pairs it with live file templates.
- CodeRush has a unified installer with account-based licensing; ReSharper's support is improving but lacks an automated over-the-wire license model.
- CodeRush tries not to override existing Visual Studio shortcuts; ReSharper takes over after a prompt.

## Relevance

Informs legacy .NET tooling practice and tool-evaluation discipline; a snapshot of the CodeRush/ReSharper rivalry within the [Visual Studio](/entities/visual-studio.md) ecosystem.
