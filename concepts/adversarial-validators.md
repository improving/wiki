# adversarial validators

Adversarial validators are critic agents that attack work an autonomous agent has produced before it is handed off. In this corpus they are a precondition for [delegation](/concepts/multi-agent-coordination.md): at maturity stages 5 and 6, work leaves human hands only once [trusted signals](/concepts/trusted-signals.md) and adversarial critics vouch for it.

## Key Claims

- Each maturity stage costs roughly seven times the effort of the one below it; delegation requires trusted signals and adversarial validators before handoff.
- Stage 5 requires trusted signals and adversarial critic agents across engineering, product, and project roles — the same gate described from three vantage points.
- Stage 6 work becomes arbitration across many parallel agent streams, coordinated with branch isolation and a merge strategy.
- The [competency floor](/concepts/competency-floor.md) never moves: Stage 5 demands developer-level skill, which is the hard gate for non-engineers, even as judgment work rises.
- Weak status gates multiply false confidence across a whole portfolio, so a validator that merely restates the agent's own output is worse than none.
- Adversarial validation is the delivery counterpart of independent verification in production systems; both exist to catch the errors a generator cannot see in itself.
