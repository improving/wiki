# Technical Debt

Technical debt is the compounding result of continually trading [Software Craftsmanship](/concepts/software-craftsmanship.md) for velocity, not a single bad decision. Across this corpus it is framed as a behavioral condition with technical symptoms — one that AI coding agents accelerate when quality standards and boundaries are absent.

## Key Claims

- Debt comes from continually trading craftsmanship for velocity, and "pay it back later" rarely happens; the root cause is behavioral, not technical.
- Uncontrolled AI generation can cost 25 to 50 percent of delivery capacity.
- AI agents take the shortest path to working code, crossing architectural boundaries invisibly; parallel agents without isolation create merge conflicts and entanglement.
- [Boundary enforcement](/concepts/boundary-enforcement.md) plus agent isolation preserves architecture at AI speed.
- A Dave Ramsey-style remedy: stop new debt with a strong [Definition of Done](/concepts/definition-of-done.md), build a safety net of tests, then invest in skills, behavior testing, and designing for the future.
