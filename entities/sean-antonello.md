# Sean Antonello

An Improving writer whose "Closing the SAP Data Gap" series addresses each C-suite role in turn — CEO, CFO, CIO, COO, CHRO — on why SAP data alone rarely answers the questions leaders ask. His through-line is that the gap between SAP and non-SAP data, and between transactions and analysis, is closed with a governed analytics layer rather than more customization.

## Topics and Work

- Argues [SAP S/4HANA](/entities/sap-s4hana.md) is a transactional system not built for easy analysis, so the close still becomes a spreadsheet scramble; a modern analytics layer changes how data is accessed, not where transactions run.
- Advocates SAP's clean core model: build customizations on [SAP BTP](/entities/sap-btp.md) so S/4 upgrades do not touch them, citing Improving's xi.Orion vendor portal built on BTP with Joule.
- Describes joining Databricks lakehouse operational data to S/4HANA financial data via SAP Business Data Cloud's zero-delta copy, then using [Databricks](/entities/databricks.md) for AI modeling.
- Positions [SAP Datasphere](/entities/sap-datasphere.md)'s business data fabric and knowledge graph as the route to self-service, with prepackaged connectors, federated or replicated access, and lineage.
- Warns that AI querying without trusted, unified data yields hallucinations, and recommends starting from one use case where better data would change a decision.
